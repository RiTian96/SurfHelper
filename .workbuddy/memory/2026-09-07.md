## 新增脚本：豆瓣观影数据导出Trakt (v1.0.0)
- 文件：`tampermonkey-scripts/douban-trakt-exporter.user.js` + 同名 `.md`，README 脚本矩阵已加行
- 功能：抓取豆瓣 电影/剧集 × 看过/想看 四类列表 → 逐条访问条目页提取 IMDb → 导出 Trakt 导入 JSON

### 豆瓣关键事实（curl 实测，后续复用）
- 列表页：`movie.douban.com/people/{uid}/{collect|wish|do}?type=movie|tv&start=0,30,60&sort=time&filter=all&mode=list`
  - **类型过滤参数是 `type=movie` / `type=tv`**（不是 subtype），剧集不需要另开域名
  - list 模式每页 30 条；`.paginator .next a`（文本「后页>」）消失即尾页；总数在 `.subject-num`（`1-30 / 2531`）
  - 单条 `ul.list-view > li.item`：ID 取 `li#list{id}`；评分 `.date span[class^="rating"]`（rating1-t~rating5-t，未评分则该元素不存在）；日期 `.date` 文本正则 `(\d{4}-\d{2}-\d{2})`
- IMDb 只能从条目页 `movie.douban.com/subject/{id}/` 的 `#info` 块取，正则 `(tt\d{5,10})`
  - 移动端接口 `m.douban.com/rexxar/api/v2/movie/{id}`（加 Referer 可匿名访问）**不含 IMDb 字段**；`api.wmdb.tv` 也不含 → 不做第三方兜底
  - curl 直连条目页被 302 到 sec.douban.com；登录态浏览器内同源 fetch 正常
- Trakt 导入入口：trakt.tv/apps/import；官方导入器主要处理 watch history/watchlist，rating 可能被忽略

### 实现要点
- 两阶段：先 fetch 翻页采全量清单去重 → 再逐条抓 IMDb（缓存 key 为豆瓣 id，实现断点续传）
- 反爬：随机 1.5-3s（三档可调）；命中 sec.douban.com/403/429 自动暂停，日志给出链接，人工验证后点「继续」
- 输出：字段顺序 imdb_id/type/watched_at/watchlisted_at/rating/rated_at；日期补 `T12:00:00Z`；评分 5星×2；超 1000 条拆文件；无 IMDb 单独导 unmatched 清单
- 测试方法：jsdom + 真实豆瓣 HTML 跑解析层冒烟（复用方式：把脚本 main(); 替换为暴露内部函数后 eval）

## v1.1.0 修复：用户实测数据不对（同一天）
用户 uid=202745100，反馈「勉强能运行但导出数据不对」，其访问 URL 不带任何参数。根因与修复：

### 豆瓣「两种浏览模式」结构差异（关键，之前只知 list 模式）
| | 列表模式 `mode=list` | 网格模式（默认，无参数/mode=grid） |
|---|---|---|
| 容器 | `ul.list-view > li.item` | `div.grid-view > div.item.comment-item` |
| 每页 | 30 条 | **15 条** |
| 豆瓣ID | `li#list{id}` | 只能取 `a[href*="/subject/"]` |
| 评分 | 嵌在 `.date` **内部** | 是 `.date` 的**兄弟节点** |
| 标题 | `.title a` | `.title a`（含 `<em>`）或 `.pic a[title]` |

- **踩坑**：选择器 `.date span[class^="rating"]` 在网格模式匹配不到 → 评分全丢。应放宽为在条目节点内 `span[class^="rating"]`
- **踩坑**：分页步长写死 30，网格模式 15 条/页会漏采一半。应取「本页实际解析条数」自适应

### 安全校验页的隐蔽特征（重要）
- 豆瓣拦截时**返回 HTTP 200**，但被 302 到 `sec.douban.com`，正文仅约 **3KB**，`<title>` 为纯「豆瓣」
- 原判据（403/429 + res.url 含 sec.douban.com + 正文关键词）抓不全 → 被误判成「该片无 IMDb」，污染未匹配清单
- 可靠判据：`text.length < 10000 && /<title>\s*豆瓣\s*<\/title>/`
- 正常条目页判据：含 `id="info"` 或正文 > 25000 字符

### 改动
解析器双模式兼容、评分选择器放宽、步长自适应、isBlocked 增强、新增 isSubjectPage、异常页记「待重跑」不记未匹配、IMDb 阶段加预检、连续异常自动降速。版本号 1.1.0，文档与 README 已同步（尚未 commit，等验收）

## v1.1.1 修复：collect 列表报「Failed to fetch」（同一天）
用户实测：wish 两个列表正常（113+16=129，与实测总数一致），但「电影·看过」「剧集·看过」稳定报 `Failed to fetch`。

### 根因（重要，通用经验）
- 豆瓣拦截时是 **302 到 `sec.douban.com`**；`fetch` 默认 `redirect: 'follow'` 会跟随跨源，
  跨源后响应没有 CORS 头 → 浏览器直接抛 `TypeError: Failed to fetch`
- **抛异常时拿不到 response 对象**，所以任何基于 `res.url` / `res.status` 的拦截判定全部失效，
  脚本只能当普通网络错误处理，进而 `break` 跳过整个列表（丢几百条）
- 解决：`fetch(url, { redirect: 'manual' })`，被重定向时得到 `res.type === 'opaqueredirect'` 或 `res.status === 0`，
  据此判定为安全校验。正常页面不受影响

### 其他改动
- 采集失败不再放弃整个列表 → 挂起并给链接，用户手动打开一次后点「继续」重试（`failGuard > 20` 才放弃）
- fetchText 加自动重试（默认 2 次，5xx 重试、4xx 直接抛）
- handleBlocked 支持直接传豆瓣条目 ID（内部拼 `/subject/{id}/`），此前会生成错误链接
- IMDb 阶段网络失败记「待重跑」而非「无 IMDb」
- 验证方式：jsdom 里 mock fetch 跑四种场景（opaqueredirect / 抖动后恢复 / 持续失败 / 正常页）

说明**不是重定向**（若是，`redirect:'manual'` 会返回 opaqueredirect）。真正的病根在：

### 关键结论（重要，以后写油猴脚本默认遵守）
- **油猴脚本里不要用页面 `fetch` 抓站，优先用 `GM_xmlhttpRequest`**
  - 页面 fetch 在 Tampermonkey 沙箱中常直接抛 `TypeError: Failed to fetch`，**拿不到任何响应对象**，无法诊断
  - `GM_xmlhttpRequest` 不受 CORS 限制，由油猴托管 Cookie，且会跟随重定向并给出 `res.finalUrl`
  - 必须在元数据声明 `@grant GM_xmlhttpRequest` + `@connect <域名>`（否则首次请求会弹授权/直接失败）
- 判据：用 `res.finalUrl` 判断跳转去向 —— 含 `sec.douban.com` = 安全校验；含 `accounts.douban.com` = 登录态失效
- 保留页面 fetch 作为 GM 不可用时的兜底
- 验证方式：jsdom 里注入假的 `window.GM_xmlhttpRequest` 跑六个场景（正常/安全校验/登录跳转/重试恢复/GM不可用回退/解析层回归）
